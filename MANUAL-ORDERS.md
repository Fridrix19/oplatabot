# Заказы и ручная выдача

## Запуск

Node.js 22+, `npm ci`, `npm start`. Для локальной работы загружается `.env`. В Render используются Environment Variables.

- `DATABASE_URL` — Internal Database URL PostgreSQL. При наличии приложение читает и записывает таблицу `store` (JSONB). Каждый запрос выполняется с блокировкой строки и транзакцией, ответ об успешной записи приходит после COMMIT. При ошибке подключения приложение не переключается молча на JSON.
- `BOT_TOKEN`, `BOT_USERNAME`, `PUBLIC_URL` — существующие настройки бота.
- `ADMIN_TOKEN` — пароль администратора (старое значение по умолчанию 55555 сохранено).
- `REVIEWS_URL` — по умолчанию https://t.me/plataotz1/3.
- `DATA_FILE` — только локальный файл или источник первого импорта, если PostgreSQL пустой. Не нужен для дальнейшего хранения при заданном DATABASE_URL.

Первый запуск создаёт таблицу и импортирует доступный файл данных. Если таблица уже заполнена, содержимое JSON её не перезаписывает. Если актуальная история находится только на временном диске старого Render-сервиса, её нужно выгрузить ДО деплоя и передать как DATA_FILE для первого импорта. История, уже потерянная при старых деплоях, из Git восстановлена не будет. Бесплатная база Render имеет срок жизни, указанный в панели: для постоянного магазина нужен тариф без срока истечения и резервные копии.

## Покупатель

Корзина убрана из навигации. Покупка одной выбранной позиции открывает оформление. После создания заказа Mini App возвращается на главную, открывает чат бота и закрывается. Inline URL открывается браузером Telegram/внешним браузером согласно настройкам клиента — сервер не может принудительно выбрать приложение браузера.

В «Мои покупки» доступна персональная история, ID/логин, зона и сервер. Пока заказ ожидает оплаты, есть кнопка «Оплатить». Через 10 минут он отменяется. После оплаты показывается «Оплачено», затем ожидание 5 минут для кодов или 5–10 минут для пополнений. Только действие администратора меняет статус на «Выдано».

## Администратор

Открыть `/admin.html`, войти, выбрать «Заказы». У оплаченного кодового товара ввести код и нажать «Выдать код». У пополнения по ID выполнить пополнение в сервисе, затем нажать «Пополнено». Повторная выдача, выдача до оплаты и один код в двух заказах отклоняются.

Бот редактирует сообщение заказа: первоначальная кнопка оплаты сменяется уведомлением об ожидании с кнопкой «Мои покупки», после выдачи — кодом под спойлером или подтверждением пополнения. Ссылка на отзывы задана. Ошибка Telegram не теряет оплаченный заказ: фоновые задачи повторяют обновление.

## Ограничения тестового контура

Страница оплаты по-прежнему ТЕСТОВАЯ: она не списывает деньги, подтверждение имитируется кнопкой. Старый открытый webhook генерации кодов отключён. Для настоящих платежей требуется отдельная интеграция, проверка суммы на сервере для всех вариантов/промокодов и сверка уведомления провайдера. Сейчас сумма принимается из существующей тестовой витрины. Случайные коды больше не генерируются.

Новые платёжные ссылки защищены случайным токеном. Старые ссылки без токена недействительны; история старых выполненных заказов остаётся доступной владельцу. Подпись Telegram проверяется, `demo`-заказы никому автоматически не присваиваются. Избранное хранится по Telegram ID, без сброса при перезапуске.

## Проверки

`npm test`: API с двумя пользователями и перезапуском; переходы оплаты/выдачи; срок; идемпотентность; поддельная авторизация; Telegram с тестовым транспортом; SQL через pg-mem. Это не заменяет проверку соединения с реальной базой Render: после деплоя в логах должны появиться `PostgreSQL connected` и `Platas API ready`.
