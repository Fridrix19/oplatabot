# Профиль пользователя

`/api/me` и `/api/me/orders` требуют подписанный Telegram `initData` в заголовке `X-Telegram-Init-Data`. Поддельный `X-Telegram-Id` не принимается. Избранное изменяется по одному элементу через PUT/DELETE `/api/me/favorites/:id`. Старые заказы с корректным Telegram ID видны владельцу; заказы `demo` автоматически никому не назначаются.

## Постоянное хранение на Render

В сервисе подключите Persistent Disk с Mount path `/var/data`. Задайте Environment variable `DATA_FILE=/var/data/store.json`. Само указание переменной без подключения диска не обеспечивает сохранность.

До деплоя выгрузите актуальный `data.json` с работающего сервера, включая покупки и коды. Перенесите его в `/var/data/store.json` до запуска новой версии, если требуется сохранить существующую историю. Не публикуйте этот файл в GitHub. При отсутствии файла программа создаёт хранилище только с каталогом; старые заказы из Git не импортируются как реальные покупки.

Запускайте один экземпляр Node.js: файловое хранилище не поддерживает несколько одновременно работающих серверов. Настройте резервное копирование диска. Для масштабирования потребуется миграция в PostgreSQL.

Локально используется существующий `data.json` рядом с сервером. Перезапуск сохраняет данные; замена файла вручную заменяет и историю. Сервер записывает изменения через временный файл и атомарное переименование. Папка проекта и файлы базы больше не доступны через статический HTTP.

Для входа в профиль открывайте приложение из Telegram. Без подписи личные API отвечают 401. BOT_TOKEN должен принадлежать тому же боту.
