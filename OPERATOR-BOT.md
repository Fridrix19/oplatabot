# Бот для ручной выдачи

Создайте отдельного бота через BotFather. В Environment веб-сервиса Render добавьте `ORDERS_BOT_TOKEN` — токен нового бота. `BOT_TOKEN` и `BOT_USERNAME` остаются настройками покупательского бота. Токены должны отличаться. `ADMIN_TELEGRAM_ID` — числовой ID администратора, которому разрешена выдача. Откройте нового бота с этого аккаунта и нажмите «Начать», затем сохраните настройки Render с перезапуском.

Бот присылает только оплаченные заказы, ожидающие выдачи, включая уже находящиеся в очереди. Неоплаченные и завершённая история не импортируются. Чтобы выдать код, используйте «Ответить» на сообщение заказа и отправьте код обычным текстом. Весь текст ответа считается кодом. Для пополнения по ID используйте кнопку «Пополнено» после фактического выполнения пополнения.

Админка и бот используют общую проверку: заказ должен быть оплачен, повторная выдача и повторное использование уже выданного кода запрещены. После выдачи сообщение оператора меняется на «Выполнен», покупатель получает результат через основной бот и в «Моих покупках». Обновление обычно занимает несколько циклов опроса (около 10–20 секунд при работающем сервере). Доступ есть только у ADMIN_TELEGRAM_ID в личном чате.

## Чеки

После выдачи бот присылает сообщение «✅ Выполнен … Ответьте на это сообщение…». Ответьте на него фото, файлом или текстом чека — основной бот отправит чек покупателю в чат. Можно прикрепить чек и заранее, ответом на карточку оплаченного заказа: он уйдёт покупателю сразу после выдачи. Для каждого заказа отправляется один чек. Ошибки отправки бот пишет в чат оператора и продолжает обрабатывать очередь.

Отдельный бот использует getUpdates: не подключайте его параллельно к другому обработчику или webhook. Оплата «Крипта» идёт через Heleket (webhook `/api/payments/heleket/webhook`), СБП и карта пока тестовые.
